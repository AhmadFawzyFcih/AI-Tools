Installation & Setup

terminal
# Install k9s
brew install derailed/k9s/k9s          # macOS
snap install k9s                        # Linux
choco install k9s                       # Windows

# Verify
k9s version

# Launch (uses current kubectl context)
k9s
💡
Prerequisite: Make sure kubectl is installed and your ~/.kube/config has contexts for each environment.
🔀

Access a Specific Dev Environment

Each dev environment (dev1, dev2, dev3…) is typically a Kubernetes namespace.

Option A — Launch directly into a namespace

terminal
# Jump straight into dev3
k9s -n dev3

# Specific cluster + namespace
k9s --context production-cluster -n dev5

Option B — Switch from inside k9s

Open namespace picker

Type :ns and press Enter

Filter for your dev

Press / and type dev3

Select & switch

Arrow to your namespace and press Enter

View pods

Type :pods — equivalent to kubectl get pods -n dev3

Switch clusters (contexts)

inside k9s
:ctx        # → list all clusters → select → Enter to switch
💎

Rails Console & Shell Access

Get into a running Rails pod to run rails c, rails s, or any command.

Find your web pod

Type :pods then /web or /puma or /rails

Shell into the pod

Select the pod and press s

Run Rails commands

You're now inside the container!

inside pod shell
# Rails Console (most common for debugging)
bundle exec rails console
# or
bin/rails c

# Rails Server (usually already running via Puma)
bundle exec rails s -b 0.0.0.0

# Database tasks
bundle exec rails db:migrate:status
bundle exec rails db:migrate

# Check routes
bundle exec rails routes | grep your_path

# Run a specific rake task
bundle exec rake your_task_name

# Quick DB connectivity check
bundle exec rails runner "puts ActiveRecord::Base.connection.active?"
💡
Multi-container pods: If your pod has sidecars, k9s will prompt you to choose which container. Pick web or rails.
⚠️
Caution: Running rails s inside an already-running pod may conflict with the existing Puma process. Use rails c for debugging.
📋

View Server Logs (Rails / Web)

Tail live Rails application logs directly from your web pods.

Find your web pod

:pods → /web or /puma

Open logs

Select pod → press l to start tailing in real time

Filter & navigate

Use the controls below to search and manage the log view

Log View Controls

l Open logs for selected pod
/ Search / filter within logs
w Toggle line wrapping
s Toggle auto-scroll
0 Show all logs (since start)
1 Last 1 minute
5 Last 5 minutes
p Previous container (crashed)
c Clear log screen
Esc Exit log view
✅
Pro tip: Press p to see logs from a previous crashed container — essential for CrashLoopBackOff debugging.

Filter patterns

in log view — press / then type
Error                 # Error lines only
ActiveRecord          # Database logs
500                   # Internal server errors
ActionController      # Controller action logs
Timeout               # Timeout issues
Memory                # Memory warnings
⚙️

View Worker Logs (Sidekiq / Background Jobs)

Workers (Sidekiq, etc.) usually run in separate pods from the web server.

Find worker pods

:pods → /sidekiq or /worker

Tail logs

Select worker pod → press l

Filter by job name

Press / → type job class name, e.g., SendEmailJob

worker log filters
WARN                  # Warnings
ERROR                 # Errors
fail                  # Failed jobs
retry                 # Retried jobs
dead                  # Dead (exhausted retries)
YourJobClassName      # Specific job class
💡
Shell into workers: Press s on a worker pod to run rails c and inspect queues or retry jobs.

Quick workflow

:pods
→
/sidekiq
→
Select pod
→
l for logs
→
/ERROR to filter

Restart Pods

Method 1 — Delete pod (auto-recreated)

Find the pod

:pods → navigate to target

Delete it

Press Ctrl+d → confirm. K8s spins up a new one automatically.

⚠️
Note: Only works if managed by a Deployment/ReplicaSet. Standalone pods won't be recreated.

Method 2 — Rolling restart (entire deployment)

Go to deployments

Type :deploy

Find & select

Filter with /web or /worker

Restart

Press r for a rolling restart

Method 3 — Scale down & up

restart methods summary
# Single pod restart
:pods → select pod → Ctrl+d → confirm

# Rolling restart (all pods in deployment)
:deploy → select deployment → r

# Scale to 0 then back up (nuclear option)
:deploy → select → s → type 0 → Enter
# wait, then:
:deploy → select → s → type 1 → Enter
📝

Modify Files Inside Pods

Quick file edits inside a running container for debugging.

Shell into the pod

:pods → select → press s

Navigate to app dir

Usually cd /app or cd /rails

Edit files

Use the editor options below

inside pod — editing files
cd /app

# vi/vim (usually available)
vi app/controllers/some_controller.rb

# Install nano if needed
apt-get update && apt-get install -y nano
nano app/controllers/some_controller.rb

# sed for quick find-and-replace
sed -i 's/old_text/new_text/g' app/models/user.rb

# Overwrite a file
cat > config/some_config.yml << 'EOF'
your_content_here
EOF

# Append a debug line
echo "Rails.logger.info 'DEBUG: here'" >> app/models/user.rb

# View files
cat app/controllers/some_controller.rb
head -50 app/controllers/some_controller.rb
grep -rn "some_method" app/
🚨
Important: File changes are temporary — lost on pod restart. Commit real fixes to Git and redeploy.

Copy files to/from pods

terminal (outside k9s)
# Copy FROM pod → local
kubectl cp dev3/pod-name:/app/config/database.yml ./database.yml

# Copy TO pod from local
kubectl cp ./fixed_file.rb dev3/pod-name:/app/app/models/fixed_file.rb

# Specify container for multi-container pods
kubectl cp ./fix.rb dev3/pod-name:/app/fix.rb -c web

Edit Kubernetes resource YAML

inside k9s
# Edit ConfigMap, Deployment, Secret, etc.
:cm → select → e       # Edit ConfigMap YAML
:deploy → select → e   # Edit Deployment YAML
:sec → select → e      # Edit Secret YAML

Extra Commands & Tips

Debugging common issues

inside k9s
# Check why a pod won't start
:events               # → OOMKilled, ImagePullBackOff, etc.

# View config maps (ENV vars)
:cm                   # → find app config → Enter to view

# View & decode secrets
:sec                  # → select → d to describe → x to decode

# Check ingress / routing
:ing                  # → routing rules & backends

# CronJobs & Jobs
:cj                   # → scheduled tasks
:jobs                 # → one-off job runs

# Cluster health
:pulse                # → cluster dashboard

# Node status
:no                   # → health, capacity, conditions

# XRAY — hierarchical tree
:xray deploy         # → deploy → replicaset → pods

Port forwarding (access Rails locally)

Select pod or service

:pods or :svc → find your Rails app

Port forward

Press Shift+f → set local:container ports (e.g., 3000:3000)

Open browser

Go to http://localhost:3000

manage port forwards
:pf                  # → list active forwards → Ctrl+d to stop

Useful shell commands inside pods

inside pod shell
# Processes, memory, disk
ps aux
free -h
df -h

# Network checks
curl -I http://some-service:3000/health
nslookup database-service

# Environment variables
env | sort
env | grep -i DATABASE
env | grep -i REDIS
env | grep -i SECRET

# Tail Rails logs
tail -f log/production.log

# Gem versions
bundle list | grep sidekiq

# Redis connectivity
redis-cli -h $REDIS_HOST ping

# Quick DB check
bundle exec rails runner "puts User.count"

# Find large files
find /app -type f -size +10M

# Check open connections
netstat -tlnp 2>/dev/null || ss -tlnp
